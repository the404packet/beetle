\section*{Abstract}

Operating system hardening is a critical aspect of cybersecurity that involves reducing the attack surface of a system by configuring it according to established security benchmarks. Despite the availability of standards such as the CIS (Center for Internet Security) Benchmarks, the process of auditing and remediating Linux systems remains largely manual, error-prone, and time-consuming. System administrators often lack a unified, automated tool that can both assess system compliance and apply remediation in a controlled, reversible manner.

This project presents \textbf{Beetle}, an automated OS hardening framework for Ubuntu Linux that implements a client--server architecture using Unix domain sockets. The system consists of a privileged daemon (\texttt{beetled}) written in C that listens for commands from a lightweight C client (\texttt{beetle}), routing them through a Bash-based handler to modular shell scripts. The framework is organized into seven auditing and hardening categories: access control, host-based firewall, initial setup, logging and auditing, network configuration, services management, and system maintenance.

Beetle features a JSON-driven, severity-tiered configuration system (basic, moderate, strict) that allows administrators to control which checks are executed. An in-memory RAM store mechanism using \texttt{/dev/shm} accelerates data access during audit and harden operations. A snapshot and restore subsystem captures the complete system state---including packages, services, firewall rules, file permissions, users, and groups---before any hardening operation, enabling safe rollback. The framework also provides a web-based dashboard built with FastAPI and React that streams audit and hardening results in real time via NDJSON, offering an interactive graphical interface with compliance visualization through donut charts and filterable result tables.

\textbf{Keywords:} OS Hardening, CIS Benchmarks, Linux Security, Automated Auditing, System Compliance, Unix Domain Sockets, Client-Server Architecture, Snapshot and Restore
